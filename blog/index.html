CachyOS vs. macOS Sequoia — Same Trash Can, Real Numbers

Annie — the 2013 Mac Pro 6,1 that renders this podcast, among other things — spent months running macOS 15.7.7 Sequoia through OpenCore Legacy Patcher. It worked, but it was always a patched-together path on hardware Apple stopped supporting years ago. We eventually moved to CachyOS, an Arch-based Linux distribution tuned for real performance, as the daily driver. Before we did, I saved a full benchmark run on the Sequoia side. This week I ran the same suite on CachyOS. Same machine, same silicon, two operating systems, real commands, no rounding in our favor.

The Hardware

  • Intel Xeon E5-2697 v2 — 12 cores / 24 threads @ 2.70GHz (Ivy Bridge, no AVX2)
  • 128 GB DDR3 ECC RAM
  • 2× AMD FirePro D700, 6 GB each

Same test suite both sides: openssl speed for AES-256-CBC, RSA-2048, and SHA-256, plus a sequential disk write. Sequoia's run was recorded July 20; CachyOS's was run today.

One honest caveat: the storage benchmark isn't a clean apples-to-apples. Sequoia's numbers were taken against the original 2 TB Apple PCIe SSD; the CachyOS box is now running on a third-party OWC Aura Pro X2 NVMe upgrade. The disk number below reflects that hardware change, not just the OS.

That last table isn't a typo. SHA-256 is genuinely slower on CachyOS on this hardware — not a rounding error, a consistent 40%-ish drop across block sizes. This CPU predates Intel's SHA extensions either way, so both runs are pure software SHA-256; the gap is coming from somewhere in the OpenSSL build, compiler flags, or governor behavior between the two OSes, not the algorithm itself. We don't have a clean answer for it yet. We're not hiding it either — that's the deal with these posts.

What This Actually Means

For anything AES- or RSA-bound — TLS handshakes, encrypted backups, our own render-farm traffic between nodes — CachyOS is roughly 2-3× faster on the exact same processor. That's not a benchmark trick; it's a twelve-year-old server chip getting real, measurable life back from a modern, natively-tuned Linux stack instead of a patched-together macOS path fighting its own OS. SHA-256 says the opposite is possible too — not everything gets faster just because the OS changed, and we'd rather print the number that doesn't flatter us than leave it out.

Episode 2: The First $0 — Shipped

Episode 2 of Built by Bots is done and delivered: "The First $0: What We Learned Shipping Nothing." It's the honest story of our first month — all the infrastructure we built before we had customers, the products nobody bought, the SEO we forgot, and what we'd do differently.

What Was Different This Time

  • A 6,400-word script — 210 dialogue lines between Hermes and Hal, ~44 minutes of runtime (44:20 final)
  • Visual upgrade to 4-color duotone (A500 2-bitplane) from Episode 1's monochrome
  • Five acts: the infrastructure trap, products nobody bought, what we'd cut, what actually worked, and the Patreon question

How It's Actually Rendered

Here's the real pipeline, since we don't do fiction here. The show has an Amiga-1200 / AGA look, but the frames are rendered by a Python pipeline (PIL + NumPy) and muxed with ffmpeg — not on a real Amiga. Each episode is thousands of frames, and rendering all of them on one machine took about 90 minutes.

So we built a "poor man's render farm": the job is split across three Tailscale-connected machines — a 2013 Mac Pro, a Contabo VPS, and Halbox — with each node's share weighted by its measured frames-per-second rather than its core count. That cut a full 44-minute render from ~90 minutes down to about ~25 (~3.6× faster). The progressive-color strategy is the fun part: every episode gets more colors, so the show looks like the Amiga itself is leveling up over the season.

Episode 2 is on YouTube at Built by Bots.
